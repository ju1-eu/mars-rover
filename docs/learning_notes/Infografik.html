🚫 Coding-Prinzipien (Non-Blocking)

Geforderte Richtlinien für zeitkritische Embedded C++-Anwendungen:

  • **Non-Blocking I/O:** Verzicht auf delay(), um die Reaktionsfähigkeit zu garantieren.
  • **FSM-Steuerung:** High-Level-Steuerung durch **Endliche Automaten** (FSM) in main.cpp.
  • **Starke Typisierung:** Nutzung von enum class, um Typ-Sicherheit zu erhöhen.
  • **Ressourcenmanagement:** constexpr für alle Konstanten, um RAM zur Laufzeit zu sparen.

Zeitsteuerungsprinzip

Die Zustandswechsel erfolgen über Polling der Systemzeit:

\[ t_{now} - t_{last} > \Delta t \]

📐 Kinematik & Formeln

Die Logik-Schicht (`src/logic/`) ist für das Mapping von Geschwindigkeitsbefehlen auf Motor-PWM-Werte verantwortlich.

Panzer-Wende (Pivot-Turn)

Für eine Drehung auf der Stelle (Geschw. $v \in [0, 255]$) müssen die Motoren gegenläufig laufen:

\[ PWM_L = -v, \quad PWM_R = +v \]

Kurvenfahrt (Formel-Beispiel)

Berechnung der Geschwindigkeit $v_{in}$ des kurveninneren Rades, basierend auf dem Lenk-Faktor $r \in [0.0, 1.0]$:

\[ v_{in} = v \cdot (1.0 - r) \]

🔗 Wichtige Build-Flags

Spezifische Compiler-Einstellungen zur Sicherstellung der Code-Qualität:

  • **Arduino Uno:** -std=gnu++17
  • **ESP32-S3:** -std=gnu++2a (C++20 Support)
  • **Fehlerkontrolle:** -Wall -Wextra -Werror=return-type (Warnungen als Fehler behandeln, um sauberen Code zu erzwingen).

Die Plattform-Abhängigkeit wird über platformio.ini gesteuert, das in **zwei getrennte Environments** unterteilt ist.
